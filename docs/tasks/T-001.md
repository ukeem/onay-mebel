# Задача T-001: Аудит проекта и готовности к чистому production-деплою
Модель: GPT-6.1 Sol, high — нужен внимательный технический и security-аудит существующего fullstack-проекта перед восстановлением production.

## Контекст

Onay Mebel — веб-сервис для мебельных компаний: пользователь собирает изделия, рассчитывает стоимость по своим материалам и фурнитуре и формирует публичное коммерческое предложение. Прежний хостинг был автоматически удалён, резервных копий PostgreSQL и uploads нет. Текущую версию нужно развернуть с чистой базой на новом Ubuntu 24.04 VPS с 2 CPU, 2 ГБ RAM и диском 40 ГБ через Dokploy; увеличение ресурсов пока невозможно.

Задача выполняется первой при подключении к существующему проекту и должна дать проверенную техническую базу для исправлений и деплоя. Прочитай `docs/product.md` полностью, особенно разделы «Ограничения и требования», «Приоритеты» и журнал решений.

## Что нужно получить

Проверенное описание фактического технического состояния проекта и однозначный вывод, можно ли безопасно разворачивать текущий коммит с чистой базой. Заполни `docs/tech.md` как справочник для следующих рабочих сессий и перечисли точные блокеры, которые требуется устранить до production.

## Границы

Входит: аудит frontend, backend, Prisma/PostgreSQL, Docker Compose, nginx, миграций и seed; проверка команд установки, сборки, тестов и статического анализа; проверка production-переменных, постоянных volumes, загрузок, внешних вызовов, ограничений ввода, auth и tenant isolation; аудит зависимостей; оценка запуска и сборки на VPS с 2 ГБ RAM; сверка старых инструкций из удалённых `.github`-файлов по истории Git с актуальным кодом и перенос подтверждённых технических фактов в `docs/tech.md`; рекомендации для T-002 и T-003.

Не входит: изменение кода, конфигурации приложения, зависимостей, Dockerfile, Compose, nginx, миграций или CI; подключение к VPS; установка Dokploy; деплой; изменение `docs/product.md`, `docs/plan.md` или файлов других задач.

## Критерии приёмки

- `docs/tech.md` содержит актуальные версии стека, структуру, команды разработки и проверок, соглашения, инфраструктуру, технические решения и известные проблемы.
- Фактически проверены backend build, frontend build, backend tests и проверки ESLint/TypeScript без автоисправления исходников; для каждой команды указан результат. Если проверку невозможно выполнить, указана конкретная причина.
- Проверена применимость `docker-compose.yml` к Dokploy и запуску через Traefik: внешние порты, сети, healthcheck, порядок старта и постоянные volumes.
- Проверен сценарий чистой базы: порядок миграций, seed, создание супер-администратора, повторный запуск и возможные побочные изменения данных.
- Проверены production-env и отсутствие секретов в Git; перечислены обязательные переменные и безопасные требования к значениям без раскрытия реальных секретов.
- Проверены auth, права доступа к данным, uploads, публичные эндпоинты, внешние запросы, rate limits и ограничения размеров; находки классифицированы как критично / важно / желательно.
- Выполнен аудит npm-зависимостей отдельно для корня, frontend и backend; результаты и применимость находок зафиксированы.
- Оценены RAM и диск при сборке и работе всех сервисов на 2 ГБ; дан конкретный минимальный план swap, лимитов/контроля ресурсов и очистки build cache для задачи деплоя.
- Отчёт отвечает, нужна ли T-002 перед деплоем, и перечисляет её точный минимальный объём. Ничего из найденного не исправлено в рамках аудита.
- Рабочее дерево после коммита содержит только исходные пользовательские изменения, если они были до начала; временных файлов, build-артефактов и логов не осталось.

## Ограничения и требования

- Задача помечена как `[аудит]`: код и production-конфигурацию не менять.
- Не запускай backend-скрипт `npm run lint`, если он включает `--fix`; используй эквивалентную проверку ESLint без изменения файлов.
- Не используй и не запрашивай реальные production-секреты.
- Значимые выводы о Dokploy, Docker, Ubuntu, Node.js, Next.js, NestJS, Prisma и PostgreSQL сверяй с актуальной официальной документацией и приводи ссылки в отчёте.
- Учитывай, что база создаётся с нуля и перенос пользовательских данных не требуется.
- Деплой должен оставаться совместимым с VPS 2 CPU / 2 ГБ RAM / 40 ГБ и доменами `onaymebel.kz`, `www.onaymebel.kz`, `deploy.onaymebel.kz`.
