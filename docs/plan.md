# План проекта

## Текущее состояние

В работе T-003: независимое review исправлений T-002 без изменения кода. Проверяются tenant isolation, uploads, публичное КП, лимиты, миграция, тесты и классификация зависимостей. Последний принятый ID: T-002.

## Запуск рабочих сессий

- По указанию владельца от 2026-10-21 все новые рабочие сессии запускаются на GPT-5.6 Sol (`gpt-5.6-sol`); модель явно указывается при запуске. Уровень усилий выбирается по сложности задачи. Смена модели — только по согласованию с владельцем.
- По указанию владельца рабочие сессии работают автономно без запросов разрешения на команды. Встроенный `create_thread` принудительно создаёт дочерние сессии с `workspace/on-request`, поэтому для реализации задач используется локальный `codex exec` в текущем checkout с явными `sandbox_mode=danger-full-access` и `approval_policy=never`. Рабочая сессия по-прежнему не пушит; приёмку и push `dev` выполняет мозг.

## Этапы

### Этап 1. Восстановление production

Цель: текущая версия Onay Mebel безопасно работает на `onaymebel.kz` с чистой базой, HTTPS, постоянным хранением данных и проверяемыми внешними резервными копиями.

### Этап 2. Стабилизация продукта

Цель: после восстановления production сверить фактическую готовность функций с продуктовым описанием и сформировать следующий план развития.

## Замечания приёмки T-001

- Реальные PostgreSQL migrations/seed/reseed, Linux image build/run, Dokploy networking и замеры ресурсов не проверены из-за отсутствия локального Linux Docker daemon и PostgreSQL; это обязательные критерии T-005/T-006.
- Единственный e2e-тест не покрывает базу и основной пользовательский сценарий; нужное покрытие распределено между T-002, T-004 и deployment smoke-тестом.
- В отчёте остался один пробел в конце строки; на технические выводы и дальнейший план это не влияет.
- Канонический домен `https://onaymebel.kz` и redirect с `www` следуют уже принятой схеме доменов. Вопросы SMS reset, бизнес-часового пояса и срока публичной ссылки нужно решить с владельцем до T-004; T-002 от них не зависит.

## Замечания приёмки T-002

- Приняты серверная tenant isolation всех восьми типов компонентов, catalog access, ownership и квоты uploads, контекстное экранирование публичного КП, CSP/iframe sandbox и согласованные лимиты входных данных.
- Подтверждены 116 backend unit/security тестов, 13 e2e, TypeScript и production build обоих приложений, Prisma generate/validate/diff и отсутствие ESLint errors. Оставшиеся audit findings классифицированы по достижимости; независимую оценку классификации выполняет T-003.
- Локально отсутствовали Docker daemon и PostgreSQL client, поэтому clean PostgreSQL `migrate deploy` дважды, Alpine image build/run и production smoke не заявлены выполненными. Это обязательные критерии T-006 до открытия production.
- Техническое предложение из отчёта: после запуска вынести Prisma CLI из постоянно работающего runtime image в отдельный migration job. Решение будет принято после T-003/T-005 и не блокирует текущую приёмку.
